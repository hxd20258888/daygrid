## 1. 产品是什么

「日格」是一个自用的个人日历清单工具，核心理念是**一张贴在桌面上的日历纸**：

- 桌面常驻日历组件，双击日期速记；
- 一个「条目 Entry」同时承载日程、待办、清单，不强迫分类；
- 每天一句复盘，周末一页周报，不做评分；
- 电脑负责整理和回看，手机负责「看今天、说一句、勾一下」。

完整设计见 `doc/日格-个人日历清单工具-产品方案-v0.1.md`（只有 md，docx 在整理时被删掉了）。

## 3. 技术栈与关键常量

| 项 | 值 |
| --- | --- |
| 桌面壳 | Electron 45.3.1（`runtime\electron.exe`，非 npm 安装） |
| 桌面数据 | sql.js 1.13.0（WASM SQLite），整库落盘 |
| 桌面前端 | 原生 JS，无打包器，CSP 限制 inline script |
| 手机端 | 原生 JS + IndexedDB，无框架 |
| Android 壳 | 原生 Java Activity + WebView + 本地 HTTP 服务器（127.0.0.1:8788） |
| 云服务 | Node 20，零依赖，JSON 文件持久化 |
| 加密 | PBKDF2-SHA256 150000 次 + AES-256-GCM |
| 测试 | playwright-core 1.65 + Edge（`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`） |

**路径常量**

- 电脑数据：`%APPDATA%\DayGrid\data\daygrid.db`，备份在 `data\backups\`（保留 30 份）
- 电脑 userData：`%APPDATA%\DayGrid`（可被 `DAYGRID_USER_DATA` 覆盖）
- 手机数据：IndexedDB `daygrid`（entries / logs / outbox / meta）
- 云服务数据：`server/data/state.json`
- 默认端口：8787

**注意：本机 PowerShell 默认带 `ELECTRON_RUN_AS_NODE=1`**，跑 Electron/测试前要 `$env:ELECTRON_RUN_AS_NODE=$null`，否则 Electron 会以 Node 模式启动并报 `Cannot find module 'electron'`。

## 4. 数据模型

### 4.1 电脑端 SQLite（`windows/db.js`）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| entries | id, space_id, title, notes, date, start_time, end_time, all_day, status, priority, list_id, tags, repeat_rule, remind_offset, estimate_min, actual_min, postponed, created_at, updated_at, deleted_at, field_ts | field_ts 是 JSON，记录每个字段的最后修改时间，用于字段级 LWW |
| lists | id, name, color, sort | 工作/生活/学习 |
| daily_logs | space_id, date, mood, summary, highlight, created_at, updated_at | 复合主键 (space_id,date) |
| changes | seq, op_id, space_id, entity, entity_id, op, fields, updated_at, device_id, created_at | 本地变更日志，同步的推送源 |
| settings | key, value | 所有配置 |
| devices / spaces / pairing_codes | — | 早期“电脑当服务器”方案遗留，现已不用 |
| fired_reminders | entry_id, date | 提醒去重 |

### 4.2 手机端 IndexedDB

- `entries`（camelCase：start/end/listId/allDay…）
- `logs`
- `outbox`（待推送的 op，op_id 主键）
- `meta`（cursor / hasSnapshot / lastSync）

**跨端字段名差异要小心**：电脑是 `start_time`，手机是 `start`；从电脑快照同步到手机时必须归一化（`applySnapshotEncrypted` 里已处理）。

### 4.3 条目状态

`todo → doing → done`，可 `canceled`；改期会累加 `postponed`。删除是软删（deleted_at）。

## 5. 同步协议与加密

### 5.1 角色

```
手机 APK ──┐
           ├── HTTP ──> 云服务器（盲存储，只存密文）
电脑客户端 ─┘
```

电脑**不再是服务器**，和手机一样是客户端。电脑关机不影响手机同步。

### 5.2 接口（`server/server.js`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/ping` | 健康检查 |
| POST | `/v1/pair` | `{code, device}` → `{deviceId, token, space}`；code 可跨空间查找 |
| POST | `/v1/spaces/:space/codes` | 需设备令牌，生成 6 位配对码（10 分钟） |
| POST | `/v1/spaces/:space/sync` | 推送 + 拉取，见下 |
| GET | `/app/*` | 手机端页面（备用，APK 已内置） |
| GET | `/download/daygrid.apk` | 从 `server/daygrid.apk` 或 `apps/android/日格.apk` 下载 |

### 5.3 sync 请求 / 响应

```json
// 请求
{
  "cursor": 12,
  "ops": [{ "op_id": "uuid", "ts": 1762934400123, "iv": "base64", "data": "base64" }],
  "needSnapshot": false,
  "snapshot": { "version": 1762934400000, "iv": "base64", "data": "base64" }
}
// 响应
{
  "cursor": 13,
  "ops": [{ "seq": 13, "op_id": "...", "device_id": "pc-xxx", "ts": 123, "iv": "...", "data": "..." }],
  "snapshot": { "version": 123, "iv": "...", "data": "..." }   // 仅 needSnapshot 时
}
```

- 服务器按 `op_id` 去重、分配 `seq`；
- 返回时排除本设备自己的 op；
- `needSnapshot` 为真且服务器有快照时返回快照；
- 快照只在 `version` 更大时被覆盖，目前只有**电脑**上传快照。

### 5.4 加密细节（两端必须一致）

```js
key = PBKDF2(passphrase, salt = "daygrid|" + spaceId, iterations = 150000, SHA-256, 32 bytes)
密文 = AES-256-GCM(key, iv = 12 字节随机)
上传格式 = { iv: base64(iv), data: base64(ciphertext || tag) }
明文结构 = { entity: "entry"|"log", entity_id, op: "upsert"|"delete", fields: {…} }
```

- 服务器看不到标题/备注，测试专门断言了 state.json 里没有明文；
- **口令丢失 = 服务器数据不可解**；电脑本地还有一份；
- 口令以明文存在电脑 SQLite settings（`cloudPass`），电脑要设登录密码。

### 5.5 冲突与合并

- entries：字段级 LWW，靠 `field_ts`；
- logs：整行 LWW，靠 `updated_at`；
- 删除是墓碑，服务器永久保留（尚未做压缩）。

## 6. 已实现功能清单

### 6.1 Windows 桌面端

- 桌面组件：透明无边框、可拖动、月历 + 今日列表、圆点、点日期切换、勾选、双击速记、滚轮翻月；
- 速记：`Ctrl+Alt+Space`，自然语言解析（今天/明天/周X/时间/#标签/!优先级/~耗时），回车保存；
- 主窗口：今天（时间轴 + 待办 + 今日一句）、日历（月视图）、复盘（完成率/时间分布/热力图/折线/顺延/MIT）、设置；
- 编辑弹窗：新建默认填下一个整点/半点 + 1 小时；
- 提醒：每 30 秒检查，Windows 通知 + 组件橙色提醒条；
- 主题：浅色 / 深色 / 透明（组件半透明），三窗口同步；
- 托盘、开机自启、全局快捷键、单实例；
- 备份、导出 JSON、清空数据；
- 云同步配置、配对码、手动同步、自动同步（60 秒 + 启动后 4 秒）。

### 6.2 手机端（APK 内置 + `apps/mobile`）

- 6 个页面：今天 / 日历 / 收集箱 / 复盘 / 我的 / 速记；
- 语音页是**模拟识别**（逐字上屏），真机语音未接；
- 数据本地 IndexedDB，离线可记可勾；
- 配对（地址 + 6 位码 + 同步口令）、手动/自动同步（2.5 秒、回前台、60 秒）；
- 未连接时顶部提示“数据只在本机”。

### 6.3 云服务

- 盲存储、配对码、设备令牌鉴权、APK 下载、手机页面托管；
- `--init` 生成空间 ID / 设备 ID / 设备令牌。

### 6.4 多租户预留

- 所有数据行有 `space_id`；
- 接口按空间划分 `/v1/spaces/:space/…`；
- 设备 token 绑定空间，配对码属于空间；
- 手机端配置里存 `spaceId`；
- **切换空间的 UI 没做**，但加空间不用改协议。

`cloud-sync-e2e.js` 会在本机起一个云服务（随机端口），验证：初始化、加密（服务器无明文）、配对、手机拉电脑数据、双向新增、修改回传。

### 7.2 打桌面安装包

没有 electron-builder，是手工组装：

1. `runtime\*` 复制到 `dist\日格\`；
2. 删 `resources\default_app.asar`；
3. 应用文件放 `resources\app\`（main.js / preload.js / db.js / sync-client.js / package.json / src / vendor / mobile / build\tray.png）；
4. `electron.exe` 改名 `日格.exe`，用 rcedit 设图标（`node_modules\rcedit`）。

改代码后要重新复制到 `dist\日格\resources\app\`。

### 7.3 打 APK

```powershell
python apps\android\build_apk.py
```

依赖（当前放在 `%TEMP%\daygrid-build\android`，临时目录可能被清）：

- JDK 17（Temurin，清华镜像）
- Android SDK：`platforms;android-33`、`build-tools;33.0.2`
- 脚本会用 `JAVA_HOME` / `ANDROID_SDK` 环境变量，找不到就退回 `%TEMP%` 路径

签名：`apps/android/daygrid.keystore`，alias `daygrid`，密码 `daygrid123`。
**必须保留这个 keystore**，否则新包无法覆盖安装。

### 关键决策记录

- 选 Electron 而不是 Tauri：机器上没有 Rust，且要快速 1:1 还原原型。
- 桌面组件用透明无边框窗口，不做 WorkerW 贴壁纸（稳定性优先）。
- 手机端坚持**一个条目模型**，不区分日程/待办。
- 语音不做“按住说话”，先做点按 + 完成（待真机验证）。
- 同步从 P2P 组网改为云盲存储：因为国内网络环境，且端到端加密后服务器不可信也没关系。
- 保留 Keystore、保留字段名归一化逻辑（跨端最容易踩的坑）。
