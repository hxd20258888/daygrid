# 日格 · 个人日历清单工具 · 产品方案

> 一张贴在 Windows 桌面上的日历纸：白天记，晚上写一句，手机随时能看。

- **文档版本**：v0.1 草案
- **日期**：2026-11-12
- **状态**：待评审（等你拍板第 12 章的 7 个问题）
- **适用对象**：个人自用，单用户，Windows 桌面 + 手机
- **文件位置**：F:\自用小工具\doc


## 一、摘要：这是什么，为什么值得做

> **「日格」是一张贴在 Windows 桌面上的日历纸**：白天双击格子记下日程和待办，晚上花一分钟写一句复盘，手机随时能看、能勾、能加。它不打算成为第二个滴答清单，只专注三件事——**记得下、看得见、坚持得住**。

和市面产品相比，本方案的差异只有三点，但都落在每天最高频的动作上：

- **桌面常驻，零窗口切换**：半透明月历贴在壁纸上，抬头就能看见，不抢焦点、不挡图标，双击即记。
- **一个条目打通日程与待办**：不用先回答「这是日历还是清单」。有时间就是日程，没时间就是待办，加子项就是清单，始终是同一个对象。
- **每天留痕，服务复盘**：完成、顺延、取消都被记录，周末自动生成一页复盘。它记录事实，不给你打分。

推荐路线：Windows 端用 **Tauri 2 + React + SQLite**（安装包约 10MB、可调 Win32 做贴桌面）；手机端复用同一套 Web 代码做 **PWA**，同步走 WebDAV 快照 / 自建轻服务；提醒用本地 Toast，并用 **ICS 订阅**写入系统日历兜底。第一个能天天用的版本约 1 个月，完整可用约 8–10 周业余时间。

文中所有需要你决定的地方，集中放在第 12 章，共 7 个问题。


## 二、背景与目标


### 2.1 现在的麻烦

这不是「没有工具」的问题，而是「工具太散」的问题。日常真实发生的是：

- 会议、缴费、取快递、朋友生日散落在微信聊天、备忘录、纸质便签和脑子里，主要靠「我记得」来记。
- 桌面日历（桌面日历、日历清单这类）能常驻桌面，但大多只能看、不能顺手改，手机端体验割裂。
- 滴答清单、Todoist 任务体系很强，但要先建项目、选清单、设日期，记一件小事要四五步；桌面常驻也不是它们的强项。
- 系统日历提醒可靠、能和手机打通，但写长一点的备注、拆子任务、做每日复盘都很别扭。
- 一天结束时想回顾「今天到底干了什么」，只剩零散的勾，没有一条时间线。


### 2.2 目标

用一句可检验的话概括：让「记一件事」和「看今天」这两个动作，在任何设备上都不超过 3 秒。

| 目标 | 衡量方式 |
| --- | --- |
| 录入快 | 唤起速记 ≤1 秒；从唤起到保存 ≤3 秒、≤2 次操作 |
| 看得见 | 开机 3 秒内桌面出现今天；不遮挡图标、不抢焦点 |
| 不断线 | 手机联网时 5 秒内看到桌面刚记的内容；断网可读、可勾 |
| 留得下 | 每天一条时间线，每周一页复盘；数据可导出，多年后仍能打开 |
| 愿意用 | 连续使用 ≥30 天，日均记录 ≥3 条 |


### 2.3 非目标（明确不做）

下面这些不是「以后再说」，而是会显著拖慢第一版、并且与「自用」定位冲突的东西，先写死：

- 团队协作、共享日历、评论与 @ 提醒；
- IM、聊天、动态流；
- 复杂项目管理：甘特图、工时、审批、OKR；
- 多用户体系与账号注册（自用就是单用户、本地优先）；
- 商业化、订阅、广告、公开分享页。


## 三、竞品扫描：别人做到了哪一步

挑 8 个有代表性的产品，从「桌面形态 / 日历与任务的关系 / 录入摩擦 / 多端 / 提醒」几个角度看一遍。以下为定性总结，依据各产品公开页面与第三方横评，仅用于判断方向。

| 产品 | 形态与强项 | 短板 | 可借鉴 |
| --- | --- | --- | --- |
| 滴答清单 TickTick | 任务 + 日历 + 番茄钟，全平台，清单体系成熟 | 桌面常驻弱；高级功能订阅；录入前要选清单和日期 | 清单与标签的平衡、日历视图里直接排任务 |
| Microsoft To Do | 免费稳定，与 Outlook / 系统日历打通 | 日历能力弱；无桌面常驻；界面偏纯列表 | 与系统提醒、系统日历的互通 |
| Todoist | 自然语言录入的标杆（「明天下午 3 点 开会」） | 桌面无日历形态；中文语义一般 | 速记框的解析体验与容错 |
| Notion Calendar | 多时区、与 Notion 任务结合、设计精良 | 强依赖 Notion；无桌面常驻；国内网络不稳 | 时间轴视觉、键盘操作 |
| Fantastical（Apple） | 自然语言、菜单栏常驻、设计标杆 | 仅 Apple 生态、付费 | 菜单栏或小组件形态的「随手看」 |
| 桌面日历 DesktopCal | 双击桌面格子记事，十几年经典，极轻 | 同步弱、迭代慢、视觉老旧 | 「双击桌面即记」的核心交互 |
| 日历清单 CalendarTask | 桌面常驻 + 多端同步 + 微信提醒 | 功能偏薄、依赖其云服务 | 桌面、手机、提醒三位一体 |
| Rainlendar | 皮肤与桌面小组件生态，资源占用低 | 配置复杂、中文化一般、同步靠第三方 | 贴在壁纸上的形态、可换肤 |


### 3.1 五条结论

- **桌面常驻是刚需，但供给两极分化**：老产品交互停在十年前，现代 Todo 工具又不做桌面。
- **「日历」和「清单」在多数产品里是两个对象**，用户被迫先分类。对个人使用，这是不必要的认知负担。
- **录入摩擦决定工具生死**：能活下来的，都是「想到就能记」的那一类。
- **手机端不需要功能对等**，需要的是「今天」随时随地可见、可勾、可加。
- **提醒的可靠性比花样重要**：在国内，系统日历、微信这类现成通道，比自建推送更稳。

所以机会不在功能数量，而在**连续性**：桌面看到 → 顺手记下 → 到点提醒 → 做完打勾 → 晚上回看 → 周末复盘。把这条链路做顺，比多做十个功能更有价值。


## 四、产品定位与设计原则

> **一句话定位**：一张贴在桌面上的日历纸——白天记，晚上写一句，手机随时能看。

边界划清楚：

| 维度 | 说明 |
| --- | --- |
| 形态 | 桌面常驻组件 + 完整窗口 + 手机 PWA，三者共用一个数据库 |
| 用户 | 只有你自己：单用户、本地优先、无账号 |
| 替代 | 桌面日历 + 备忘录 + 半个 Todo 工具 |
| 不替代 | 系统日历。通过 ICS 单向互通，借用它的系统级提醒 |
| 气质 | 安静、纸感、不催促；记录事实，不做评判 |


### 4.1 六条设计原则

| 原则 | 含义 | 落地例子 |
| --- | --- | --- |
| 三秒法则 | 记录路径 ≤3 秒、≤2 次操作 | 快捷键 → 一句话 → 回车，日期标签自动解析 |
| 窗口退让 | 桌面组件不抢焦点、不挡内容 | 半透明、可穿透、贴壁纸层、锁定位置 |
| 一个条目 | 不强迫用户先分类 | 有时间是日程，没时间是待办，加子项是清单，同一个对象 |
| 记录优先 | 完成与未完成都值得留痕 | 顺延有次数、有原因，不羞辱用户 |
| 本地优先 | 断网可用，数据能带走 | SQLite 本地库 + 每日备份 + JSON / Markdown 导出 |
| 克制 | 默认零配置，功能按需出现 | 首屏只有今天；高级设置全部折叠 |

其中「一个条目」是整个方案的结构基石，第 5 章会展开。它带来的直接好处是：你永远不需要在「新建日程」和「新建任务」之间做选择，也就少了一次犹豫——而犹豫正是速记最大的敌人。


## 五、核心概念与信息架构


### 5.1 唯一的核心对象：条目 Entry

整个产品只有一个核心对象：条目（Entry）。它同时承载日程、待办、清单三种用法，靠字段区分，而不是靠类型区分。这是与多数产品最大的结构差异。

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| title | 标题，必填，一行 | 和张总过方案 |
| date | 日期，默认今天 | 2026-11-13 |
| start_time / end_time | 起止时间；有则进时间轴，无则进当日待办 | 15:00 – 16:00 |
| all_day | 全天事项（生日、纪念日） | 是 |
| status | 待办 / 进行中 / 完成 / 取消 | 完成 |
| checklist | 轻量子项，带勾选与进度 | ①改预算 ②发邮件 |
| notes | 备注，轻量 Markdown，可粘链接 | 会议链接… |
| tags | 标签，多对多，可跨清单聚合 | #工作 #客户 |
| list | 清单，单归属，用于分区与配色 | 工作 |
| priority | 四档：无 / 低 / 中 / 高 | 高 |
| repeat | 重复规则（RRULE 子集）+ 例外日 | 每周一 |
| remind | 提前 N 分钟 / 准点 / 自定义 | 提前 10 分钟 |
| estimate / actual | 预计与实际耗时，可选 | 30m / 45m |
| created_at 等 | 创建、更新、删除时间，用于同步与回收站 | 毫秒时间戳 |

判断规则只有一条：**有没有 start_time**。有，就出现在时间轴；没有，就出现在当日待办区。你永远不需要回答「这是日程还是任务」。


### 5.2 五个空间

| 空间 | 作用 | 默认视图 |
| --- | --- | --- |
| 今天 Today | 每天打开的第一屏：时间轴 + 待办 + 进度环 | 日 |
| 日历 Calendar | 月 / 周 / 日切换，拖拽排期 | 月 |
| 收集箱 Inbox | 还没想好放哪天的事，先扔进来 | 列表 |
| 复盘 Review | 每日一句、周复盘、年热力图 | 周 |
| 搜索 Search | 全局检索，Ctrl+K | 列表 |

「清单 Lists」（工作 / 生活 / 学习）是分类维度，不占主导航，折叠在侧边栏里。目的是让首屏足够安静。


### 5.3 状态机

待办 → 进行中 → 完成；待办 → 顺延（记录次数与原因）；任意状态 → 取消。

**顺延不是失败，是数据。** 连续顺延 3 次的事项会被标记为「要么拆小，要么删掉」，这比任何效率理论都更能帮你清理积压。取消同理：诚实地放弃，比长期挂着更有价值。


### 5.4 信息架构

| 一级 | 二级 | 说明 |
| --- | --- | --- |
| 今天 | 时间轴 / 今日待办 / 进度与一句总结 | 06:00–24:00，当前时间红线 |
| 日历 | 月 / 周 / 日；重复事项与例外日 | 拖拽改期、拖拽排期 |
| 收集箱 | 未整理条目 | 一键分配日期或转为清单 |
| 复盘 | 日回顾 / 周复盘 / 年热力图 | 自动汇总，不手填 |
| 设置 | 外观 / 提醒 / 数据 / 通用 | 全部折叠分组 |


## 六、功能方案

下面按「桌面 → 录入 → 组织 → 复盘 → 提醒 → 数据」的顺序展开。每块都给出交互细节和验收标准，方便后续直接照着做，也方便你判断哪些可以砍。


### 6.1 桌面常驻日历

这是产品的「脸」。目标只有一句：开机就在，抬头可见，不碍事。

| 形态 | 说明 | 技术难度 | 计划 |
| --- | --- | --- | --- |
| 壁纸层 Wallpaper | 嵌在桌面图标之下、壁纸之上，最沉浸，和壁纸融为一体 | 高：需注入 WorkerW，Win11 各版本差异大 | 默认关闭，M4 作为加分项 |
| 悬浮组件 Widget | 无边框半透明，可置底或置顶，可鼠标穿透 | 低：稳定、兼容性好 | **默认形态** |
| 完整窗口 Window | 常规应用窗口，功能齐全 | 低 | 双击组件或托盘打开 |

**交互明细：**

- 单击日期：在旁边浮层显示当日条目；再点空白处关闭。
- 双击日期：就地弹出速记输入框，回车即存，**不打开大窗口**。
- 滚轮：翻月；Ctrl + 滚轮：缩放组件大小。
- 拖拽条目到另一天：改期；拖到时间轴：排期并同时设定时间。
- 悬停日期：显示当日前 3 条与「还有 N 条」。
- 右键菜单：新建、回到今天、锁定位置、透明度、切换形态、退出。
- 记忆位置、大小、透明度、所在显示器；多屏可各自独立或镜像。
- 鼠标穿透开关（托盘或快捷键），穿透时仍可用快捷键唤起速记。
- 「今天」格子上画进度环，一眼看到今天完成了多少。

**尺寸与视觉**：默认 320×360 的月历，另提供 420×120 的「今日条」（只显示今天和接下来 3 条）。字体跟随系统，深浅色自动切换，圆角 8px，整体透明度默认 85%。

**验收标准：**

- 开机 3 秒内出现；内存占用 <150MB；空闲 CPU <1%。
- 默认落在桌面右侧空白区，首次启动有一次拖动引导，不压住常用图标。
- 全屏游戏、投屏演示时自动隐藏（可配置）。
- 多屏 150% / 200% 缩放下不模糊、不错位。


### 6.2 极速录入

这是产品的「手」。所有设计围绕一件事：想到就能记，不打断手上正在做的事。

- 全局快捷键 **Ctrl+Alt+Space**（可改）唤起一条 640px 宽的居中输入条，背景轻微模糊，不切全屏。
- 输入自然语言，实时高亮解析出的日期、时间、标签；回车保存，Esc 取消。
- 保存后**输入条不关闭**，可以连续录入；3 秒无操作自动淡出。Ctrl+Enter 保存并打开详情。
- 默认落到「今天」；解析不出日期就进「收集箱」，绝不弹错误框。
- 支持粘贴多行：每行生成一个条目，用于批量导入。
- 从微信、浏览器复制文本后按快捷键，自动填入输入框并尝试解析。
- 手机端：底部常驻「+」，调用系统听写；iOS 可配「快捷指令」一键速记。

**自然语言示例（首版支持范围）：**

| 你输入 | 解析结果 |
| --- | --- |
| 明天下午3点 和张总过方案 | 明天 15:00，标题「和张总过方案」 |
| 周五 10:00-11:30 项目评审 #工作 | 本周五 10:00–11:30，标签「工作」 |
| 每周一 9:00 周会 !高 | 重复：每周一；优先级：高 |
| 每月5号 交房租 @生活 | 每月 5 日；清单「生活」 |
| 30号前 写完季度总结 ~2h | 本月 30 日；预计 2 小时 |
| 取快递 | 无时间 → 今日待办 |
| 下周三 妈妈生日 全天 | 下周三；全天事项 |

**解析原则：宁可少解析，不可解析错。** 拿不准时保留原文为标题、日期默认今天，用户一键就能改；已解析的片段在输入框里高亮，点一下即可取消该片段。这条原则比多支持十种说法重要得多。


### 6.3 日程与任务

- **日视图**：06:00–24:00 时间轴，当前时间红线，重叠事项并排显示，全天事项置顶。
- **周视图**：7 列，适合排下一周；**月视图**：格子 + 圆点或条数，信息密度可调。
- **拖拽**：左右移改日期，上下拖改时间，拉边缘改时长，支持跨视图拖拽。
- **重复**：每天 / 工作日 / 每周几 / 每月 N 日 / 每年；改动时可选「仅这次 / 这次及以后 / 全部」；支持跳过某次、单独改期某次。
- **子任务**：条目内 checklist，勾选进度显示在条目上（如 2/5）。
- **备注**：轻量 Markdown（粗体、列表、链接），不做富文本编辑器——克制是刻意的。
- **标签与清单**：标签跨清单聚合，清单用于分区；颜色只给清单，避免满屏花。
- **优先级**：无 / 低 / 中 / 高，只有「高」在视觉上强调，其余弱化。
- **批量**：框选或 Shift 多选，批量改期、改清单、删除。
- **撤销**：删除或改期后 10 秒内 Ctrl+Z 可撤销。
- **搜索**：Ctrl+K 搜标题、备注、标签，支持「#工作 上周」这类组合条件。


### 6.4 每日进程与复盘

这一块是「日历清单」和普通 Todo 的分水岭。目标不是考核自己，而是留下可回看的痕迹。

**日回顾（当天 21:30 或首次空闲时轻提示，可关）：**

- 进度环：今日完成 4/7，顺延 1。
- 时间线：自动记录每条目的创建、开始、完成、顺延时间，形成「这一天」的流水。
- 每日一句 + 心情（5 档）+ 今日亮点（一条即可）。
- 可选三问：今天做成了什么？什么没做成、为什么？明天最重要的一件事？

**周复盘（周日 20:00 或周一早上弹出，可关）：**

- 完成率、按时完成率、顺延次数 Top 5。
- 时间分布：按清单 / 标签统计（基于预计或实际耗时）。
- 连续记录天数；本周新增 / 完成 / 取消。
- 下周 3 件最重要的事（MIT），一键生成下周条目。
- 一键导出单页 Markdown 或图片，存本地或发给自己。

**年视图**：GitHub 式热力图，颜色深浅表示当日完成数，点开某天可回看。年底生成「这一年」：条目数、完成率、高频标签、最长连续天数。

> **克制条款**：不做评分、不做排名、不做「效率分」。自用工具一旦开始评判用户，离被卸载就不远了。


### 6.5 提醒

| 场景 | 方案 |
| --- | --- |
| 桌面准点提醒 | Windows Toast 通知（本地），带「完成 / 稍后 / 打开」按钮 |
| 提前量 | 提前 5 / 10 / 15 / 30 / 60 分钟，可按条目单独设置 |
| 强提醒 | 未处理则每 5 分钟重复一次，最多 3 次（可配） |
| 稍后提醒 | 10 分钟后 / 1 小时后 / 今晚 20:00 / 明天早上 |
| 免打扰 | 可设时段（如 23:00–07:00），期间只记录不弹窗，次日汇总 |
| 错过补偿 | 开机或唤醒时提示「你错过了 3 条」，可批量顺延 |
| 手机提醒 | PWA Web Push（Android 较好；iOS 需 16.4+ 且添加到主屏） |
| 兜底通道 | 生成 ICS 订阅链接导入手机系统日历，用系统级提醒，最可靠 |
| 可选外推 | 企业微信机器人 / Telegram Bot / Server酱 / 邮件，自用成本几乎为零 |

建议默认只开「桌面 Toast + ICS 兜底」。推送这件事，**稳定比花哨重要**；不要让提醒本身变成新的负担。


### 6.6 数据、备份与同步（功能层）

- 本地 SQLite 单文件，默认在 %APPDATA%\DayGrid\data.db，可改到自选目录（比如同步盘）。
- 每日自动备份：启动时若当天未备份，复制一份到 backups/，保留 30 天；另有「立即备份」。
- 回收站：删除进回收站，30 天后清理，期间可恢复。
- **导出**：JSON（全量，含 ID 与时间戳，用于迁移）、Markdown（按天 / 按月，适合归档与写作）、ICS（导入系统日历）、CSV（表格分析）。
- **导入**：JSON 全量恢复、ICS 导入（只读同步系统日历）、Markdown 待办列表。
- 同步：见第 8 章。界面上只暴露三件事——同步状态、最后同步时间、冲突怎么处理。


### 6.7 设置与个性化

| 分组 | 项目 |
| --- | --- |
| 外观 | 主题（浅 / 深 / 跟随系统）、强调色、字号、组件透明度与尺寸、是否显示农历 |
| 行为 | 开机自启、关闭到托盘、单实例、双击组件打开完整窗口、全屏时隐藏 |
| 快捷键 | 速记、显示 / 隐藏、回到今天、搜索；全部可改，带冲突检测 |
| 时间 | 周起始日（周一 / 周日）、24 小时制、时区、默认提醒提前量 |
| 数据 | 数据目录、备份策略、导出、导入、回收站、同步配置 |
| 关于 | 版本、检查更新、日志目录、开源许可 |


### 6.8 可选增强（P3，主线做完再考虑）

- **专注计时**：条目上启动正计时或番茄钟，结束后回填实际耗时，喂给统计。
- **习惯打卡**：喝水、运动、阅读，按周几设置，日历上以点阵显示。
- **纪念日 / 倒计时**：生日、纪念日、项目截止，桌面组件显示「还有 N 天」。
- **截图附件**：把截图拖到某天作为当日记录，仅本地存储，不进同步。
- **模板**：晨间清单、周复盘、旅行打包，一键生成一组条目。
- **AI 辅助**（可选、需联网、默认关闭）：一句话拆子任务、把一周记录写成周报、自然语言查询「上个月在客户上花了多少时间」。密钥自填，不上传原始数据。

排序原则：**先用满 30 天，再按真实需求加。** 这一节里的东西，绝大多数在第一版都不该存在。


## 七、移动端方案


### 7.1 定位

手机端不是桌面端的缩小版，而是「口袋里的今天」：看今天、快速加、随手勾、临时改期。复杂的整理、批量操作、复盘写作，回到桌面做。承认这一点，能省掉一半工作量。


### 7.2 形态选择

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| PWA | 一套 Web 代码；免安装免审核；可加主屏；更新即时 | iOS 推送受限；读不到系统日历 | **首选**，覆盖约 90% 场景 |
| Capacitor 套壳 | 可上架或侧载；原生通知与日历权限 | 多一套构建与签名；iOS 需开发者账号 | 需要可靠通知时再做 |
| 微信小程序 | 分享方便；订阅消息 | 需审核与类目；离线能力弱 | 不做 |
| 原生双端 | 体验最好 | 成本约 3 倍，自用不划算 | 不做 |


### 7.3 移动端信息架构

| 页签 | 内容 |
| --- | --- |
| 今天 | 日期 + 进度环 + 时间轴 + 待办；右滑完成、左滑延期、长按拖动 |
| 日历 | 月视图，点日期看当日；底部「+」速记 |
| 收集箱 | 未排期条目，可批量分配日期 |
| 我的 | 清单管理、复盘入口、设置、同步状态 |

只有四个页签，对应四个动作：看、排、收、设置。手机上不做标签管理、不做批量编辑、不做统计图表——那些留给大屏。


### 7.4 交互要点

- 首屏 3 秒内看到今天，默认滚动到当前时间附近。
- 底部悬浮「+」，点开即输入，键盘弹出不遮挡输入区；支持系统听写。
- 勾选有轻微动效；Android 上给一次震动反馈。
- **离线可读可勾**，操作进本地队列，联网后自动同步；冲突时提示，绝不静默覆盖。
- 深色模式跟随系统；字号跟随系统放大，不做死板像素。
- 锁屏 / 主屏小组件：Android 用 Capacitor 后可以做；iOS 先用「快捷指令 + URL Scheme」实现一键速记。


### 7.5 通知的现实

iOS 的 Web Push 需要 16.4+、必须「添加到主屏幕」，且国内网络下稳定性一般。因此手机端的可靠提醒走两条腿：一是 PWA 推送（能通则用），二是 **ICS 订阅写入系统日历**（一定通）。

这也解释了本方案为什么**不把自建推送服务当前置条件**：能用现成通道解决的，就不要自己养一个服务。


### 7.6 验收标准

- 手机浏览器首屏 <1.5 秒；添加到主屏后图标与启动图正常。
- 离线勾选 5 条，联网后 5 秒内同步完成。
- 横屏、平板、折叠屏布局不崩。
- 连续一周在手机上完成「看今天 + 勾选」而不觉得别扭。


## 八、技术方案


### 8.1 选型对比

| 方案 | 包体 / 内存 | 桌面能力 | 代码复用 | 主要风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Tauri 2 + React + SQLite | 约 10MB / 80MB | Rust 可调 Win32，透明、贴桌面、全局快捷键都能做 | Web 前端可复用到 PWA | Rust 学习曲线；插件生态较新 | **推荐** |
| Electron + React | 约 120MB / 250MB | 成熟，Node 生态全 | 同上 | 体积内存大；贴桌面仍需 native 模块 | 备选 |
| Flutter 全端 | 约 30MB / 120MB | 窗口能力靠插件，贴桌面麻烦 | Dart 一套 | 壁纸层难做；Web 复用为零 | 不推荐 |
| .NET WinUI 3 + 移动端 | 小 / 低 | 原生最好 | 无，双份开发 | 成本翻倍 | 不推荐 |
| 纯 Web | 0 | 无桌面常驻 | 100% | 不满足「桌面工具」这个核心诉求 | 仅作移动端 |

**推荐组合**：Tauri 2（Rust）+ React 18 + TypeScript + Vite + SQLite + Tailwind CSS + Zustand + date-fns + RRule.js。桌面与 PWA 共享一个 `core` 包（模型、解析、重复规则、统计），只替换「存储适配器」和「系统能力适配器」。


### 8.2 架构

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 客户端壳 | Windows：Tauri 2 + Rust；手机：PWA | 窗口、托盘、全局快捷键、Toast、贴桌面；主屏与推送 |
| 界面层 | React 18 + TypeScript + Tailwind | 今天 / 日历 / 复盘 / 设置四个空间 |
| 领域层 | packages/core（纯 TS，无 IO） | Entry 模型、自然语言解析、重复规则、统计 |
| 存储层 | SQLite（桌面）/ IndexedDB（Web） | 本地优先，统一 Repository 接口 |
| 同步层（可选） | packages/sync + Worker/D1 | 增量 oplog、LWW、冲突副本 |
| 外部集成 | ICS / WebDAV / Bot / 系统日历 | 兜底提醒与数据互通 |

数据流很简单：界面只调 `core` 的用例函数，用例函数只依赖 Repository 接口；桌面注入 SQLite 实现，Web 注入 IndexedDB 实现。这样同一份业务逻辑不会写两遍，也保证了「桌面能做的，手机逻辑上也能做」。


### 8.3 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| entries | id, title, notes, date, start_time, end_time, all_day, status, priority, list_id, repeat_rule, remind_offset, estimate_min, actual_min, created_at, updated_at, deleted_at, rev, device_id | 主表 |
| checklists | id, entry_id, title, done, sort | 子项 |
| lists | id, name, color, sort | 清单 |
| tags / entry_tags | id, name / entry_id, tag_id | 多对多 |
| daily_logs | date, mood, summary, highlight, created_at, updated_at | 每日一句 |
| recurrences | entry_id, rrule, exceptions(JSON) | 重复与例外 |
| reminders | id, entry_id, fire_at, channel, state | 待触发提醒队列 |
| settings | key, value | 配置 |
| oplog | seq, entity, entity_id, op, payload, updated_at, device_id | 同步日志 |
| attachments | id, entry_id, path, mime | 本地附件（可选） |

**索引建议**：entries(date)、entries(status)、entries(updated_at)、oplog(seq)、reminders(fire_at, state)。

**两个容易踩的细节**：ID 用 UUIDv7（时间有序，便于分页与同步）；时间统一存 UTC 毫秒，但**全天事项单独存本地日期字符串**，否则跨时区出差时生日会漂移一天。


### 8.4 同步方案

自用场景的约束是：设备少（2–3 台）、写入冲突低，但要求「不能丢数据」且「实现别太重」。所以分两步走，而不是一上来造轮子。

**方案 A · WebDAV 快照（MVP，1–2 天）**：整库导出为加密 JSON，带 version 与 device_id；启动、退出、每 5 分钟检查远端 version；不一致则拉取并按 updated_at 合并，冲突保留 `.conflict` 副本。适配坚果云、Nextcloud、群晖。

**方案 B · 增量 oplog（正式版，3–5 天）**：本地记录每次变更，带 seq 与 device_id；push 自 last_cursor 起的变更，pull 服务端新变更；字段级 LWW，删除用墓碑；服务端用 Cloudflare Workers + D1（个人免费额度足够）或 Supabase。

| 对比项 | A 快照 | B 增量 |
| --- | --- | --- |
| 实现成本 | 低，1–2 天 | 中，3–5 天 |
| 冲突处理 | 整库覆盖，粒度粗 | 字段级，粒度细 |
| 流量 | 全量，库大时浪费 | 增量，长期更省 |
| 适用 | 单设备切换、备份 | 多设备准实时 |

**结论**：先用 A 把「手机能看到」跑通，B 作为正式方案。两者共用同一份导出 / 导入代码，切换成本很低。


### 8.5 关键技术点与坑

| 技术点 | 做法 | 已知的坑 |
| --- | --- | --- |
| 贴桌面（壁纸层） | 找到 WorkerW 窗口，SetParent 把自己的 HWND 挂上去 | Win11 24H2 结构有变化；Explorer 重启后失效需重挂；多屏只支持主屏 |
| 透明 / 无边框 | Tauri window transparent + decorations(false) | 透明窗口的点击区域、阴影、圆角在 Win10 上表现不同 |
| 鼠标穿透 | WS_EX_LAYERED + WS_EX_TRANSPARENT | 穿透后无法交互，必须留快捷键或托盘开关 |
| 全局快捷键 | tauri-plugin-global-shortcut | 与输入法、其他软件冲突，必须可改键 |
| Toast 通知 | tauri-plugin-notification + 设置 AppUserModelID | 不打磨 AUMID 时通知不显示，这是最常见的坑；安装版才稳定 |
| 开机自启 | 注册表 Run 或任务计划 | 便携版路径变化后失效 |
| 单实例 | 命名互斥体 / single-instance 插件 | 第二次启动应唤起已有窗口，而不是开新库 |
| 高 DPI | 逻辑像素布局 + 多倍图 | 150% / 200% 下模糊、组件错位 |
| 重复日程 | RRule 展开 + 例外表 | 月末 31 号、闰年、DST 边界 |
| 时区 | 存 UTC，全天存本地日期 | 跨时区时全天事项漂移 |


### 8.6 工程结构

| 目录 | 内容 |
| --- | --- |
| apps/desktop | Tauri + React 桌面端，Rust 侧放 Win32 相关代码 |
| apps/web | PWA，移动端优先 |
| packages/core | 模型、NLP、RRULE、统计（纯函数，重点单测对象） |
| packages/ui | 共享组件与主题 |
| packages/sync | 同步引擎（快照与 oplog 两种实现） |
| services/sync | 可选的同步服务（Worker + D1） |


### 8.7 质量与测试

- `core` 单测覆盖重复规则、自然语言解析、同步合并，覆盖率目标 ≥80%。
- Playwright 跑 Web 端主流程：新建 → 勾选 → 改期 → 搜索 → 导出。
- 桌面端手工清单：多屏、DPI、休眠唤醒、断网、Explorer 重启。
- 每次发版前跑「旧库升级」测试：从上一版数据库启动，确认不丢数据。


### 8.8 发布与更新

Windows 安装包（NSIS 或 MSI）+ 便携版 zip；用 Tauri Updater 做自动更新（自签或 GitHub Releases）；语义化版本号 + 更新日志。自用其实**便携版 + 手动覆盖**就够，先把安装版留给「通知要稳定」这件事。

## 十、风险与对策

| 风险 | 影响 | 对策 |

## 十一、成功标准

自用工具也需要标准，否则永远在「再加一个功能」。30 天后逐条对照：

- 仍在用，且桌面组件常开；
- 日均记录 ≥3 条，每月至少完成 2 次周复盘；
- 从想到一件事到记下来 ≤3 秒；从开机到看见今天 ≤3 秒；
- 手机端每周至少打开 5 次；
- 数据能完整导出，并在另一台机器恢复；
- 不再需要「桌面日历 + 备忘录 + 另一个 Todo」三件套。

| 撤销 | Ctrl + Z | 10 秒内有效 |
| 切换日 / 周 / 月 | 1 / 2 / 3 | 应用内 |
