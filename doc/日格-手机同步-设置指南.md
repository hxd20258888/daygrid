# 日格 · 云同步部署与使用指南（v0.2）

Tailscale 在国内不可用，所以同步改成“自己的云服务器 + 端到端加密”：

```
手机 APK ──┐
           ├── HTTPS/HTTP ──> 你的云服务器（只存密文）
电脑客户端 ─┘
```

服务器只负责排序和转发，**它看不到你的日程内容**；加密口令只在电脑和手机上。

---

## 一、买一台服务器（你做）

- 阿里云/腾讯云“轻量应用服务器”，最低配（2 核 2G）就够，约 ¥24–40/月；
- 镜像选 **Ubuntu 22.04**；
- 记下公网 IP；安全组/防火墙放行 **TCP 8787**。

> 不需要域名，也不需要备案：备案只针对 80/443 端口，我们用 8787。

## 二、部署服务端（你做，约 10 分钟）

SSH 登录服务器后：

```bash
# 1. 装 Node 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v        # 应该是 v20.x

# 2. 把本机的 server 目录传上去（在 Windows 上执行）
#    scp -r F:\自用小工具\server root@你的服务器IP:/opt/daygrid

# 3. 初始化，生成空间 ID 和设备令牌
cd /opt/daygrid
node server.js --init
```

会打印三行，**抄下来**：

```
空间 ID    : personal
设备 ID    : pc-xxxxxxxx
设备令牌   : 一长串
```

```bash
# 4. 启动（先临时跑，验证通了再设开机自启）
PORT=8787 nohup node server.js > daygrid.log 2>&1 &
curl http://127.0.0.1:8787/v1/ping   # 返回 {"ok":true,...} 就成了
```

开机自启（可选，但建议）：

```bash
sudo tee /etc/systemd/system/daygrid.service > /dev/null <<'EOF'
[Unit]
Description=DayGrid Sync
After=network.target

[Service]
WorkingDirectory=/opt/daygrid
ExecStart=/usr/bin/node server.js
Environment=PORT=8787
Restart=always

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now daygrid
sudo systemctl status daygrid
```

## 三、配置电脑端（你做）

日格 → 设置 → 云同步：

| 字段 | 填什么 |
| --- | --- |
| 服务器地址 | `http://你的服务器IP:8787` |
| 空间 ID | 初始化打印的 `personal` |
| 设备 ID | 初始化打印的 `pc-xxxxxxxx` |
| 设备令牌 | 初始化打印的那一长串 |
| 同步口令 | **自己想一个，至少 6 位**，手机要填同一个 |

点「保存并同步」。第一次会把本机数据加密后传上去。

然后点「生成配对码」，得到 6 位数字，手机配对用。

## 四、配置手机（你做）

1. 安装 APK（见下）；
2. 打开 → 我的 → 数据与同步：
   - 地址：`http://你的服务器IP:8787`
   - 配对码：电脑上那 6 位
   - 同步口令：**和电脑一模一样**
3. 点「连接」，第一次会拉下电脑的数据。

### 装 APK

把安装包传到服务器（在 Windows 上执行）：

```bash
scp F:\自用小工具\apps\android\日格.apk root@你的服务器IP:/opt/daygrid/daygrid.apk
```

然后手机浏览器打开 `http://你的服务器IP:8787/download/daygrid.apk` 下载安装，提示“未知来源”时允许。

也可以直接用数据线或微信把 `apps\android\日格.apk` 传到手机。

## 五、加密是怎么做的

- 口令 → PBKDF2-SHA256（15 万次，盐 = `daygrid|空间ID`）→ 256 位密钥；
- 每条变更的内容用 AES-256-GCM 加密，服务器只存 `{iv, 密文}`；
- 服务器上**没有明文标题、备注**，测试里专门验证过；
- **口令丢了，服务器上的数据就解不开**（电脑本机的数据还在，可以重设口令重新上传）。

注意两点：

1. 传输是 HTTP（没有域名和证书），但内容是密文；设备令牌是明文传输，泄露了最多能往你的空间塞垃圾数据，看不到内容，也解不开。
2. 电脑本机的设置表里保存了口令（为了自动同步），所以电脑本身要设登录密码。

---

## 六、同步行为

- 电脑：改完 60 秒内自动推；启动 4 秒后自动同步一次；
- 手机：改完 2.5 秒推、回到前台拉、每 60 秒拉一次，也可以手动点「同步」；
- 冲突按字段比时间，电脑改标题、手机改备注会都保留；
- 删除是墓碑，避免离线设备复活旧数据；
- 第一次同步拉快照，之后是增量。

## 七、常见问题

**手机连不上**
1. 服务器上 `curl http://127.0.0.1:8787/v1/ping` 是否正常；
2. 安全组是否放行 8787；
3. 手机浏览器直接打开 `http://IP:8787/v1/ping` 看有没有 JSON。

**配对提示“配对码无效或已过期”**
配对码 10 分钟有效，电脑上重新生成。

**同步成功但手机看不到内容**
同步口令和电脑不一致，密文解不开会被跳过。两台设备改成一模一样再同步。

**电脑上显示“设备被吊销”**
服务器上删掉设备或重新 `--init` 了，重新配对。

**服务器数据在哪**
`/opt/daygrid/data/state.json`，全是密文；备份这个文件即可。

---

## 八、成本与安全建议

- 最低配轻量服务器足够，流量几乎可以忽略（每次同步几 KB）；
- 把 SSH 改成密钥登录、关掉密码登录；
- 如果以后想要 HTTPS，可以绑域名 + Let's Encrypt（需要备案），但内容是密文，收益有限。
